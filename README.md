## 它是什么

DeepSeek Harness 启动时先播一段六幕的开机动画（黑屏描边 → 过曝白闪 → 技术档案 → 权限门 → 核验 → 进入），
然后停在一道**验证门**前：输 PIN、按指纹、或者填验证器动态码，三者任意一个通过才进得去工作区。

它不是"开机自启个小窗"那种装饰，是**档在应用前面的最后一步**。

## 三种开门方式

| 方式 | 说明 |
|---|---|
| **访问 PIN** | 4–8 位数字，scrypt 加盐哈希存本地，连续错 5 次锁 30 秒 |
| **Windows Hello** | 调用系统凭据验证（指纹 / 人脸 / Hello PIN），并把系统窗口强制置顶，不会被应用挡住 |
| **验证器动态码** | 标准 TOTP（RFC 6238），手机扫码或手输密钥即可，**完全离线**；配 8 个一次性备用码防手机丢失 |

## 安装

```powershell
# 1. 克隆到任意目录
git clone https://github.com/zoushangkun-dev/dsh-startup-auth-cn.git

# 2. 装进 desktop profile（link 方式，改代码即时生效）
& "D:\dsh\resources\runtime\cli\bin\dsh.cmd" plugin --profile desktop add "link:<克隆到的路径>"

# 3. 重开客户端
```

Windows 用户也可以直接双击仓库里的 `安装.cmd`（会先检查客户端是否已退出）。

> 装在哪个路径都可以，但**不要放在会被清理的临时目录**——profile 里存的是软链。
> 客户端运行中直接装通常会成功（实测 pnpm 3.7 秒）；如果报 `EPERM ... package.json.lock`，退出客户端再装。

## 首次使用

1. 重新打开客户端，动画播完会出现验证门；
2. 先设一个 4–8 位 PIN（这一步会同时把你放进去）；
3. 之后再启动，可以直接输 PIN，也可以点「用验证器 6 位码进入」先配好验证器。

**强烈建议配置验证器**：点「设置验证器（6 位动态码）」→ 屏幕给出 32 位密钥 + 8 个备用码 →
手机装 Microsoft Authenticator / Google Authenticator，选「其他账户 → 输入代码」，把密钥粘进去。

> 那 8 个备用码**只显示一次**，请抄在纸上或存进密码管理器。手机丢了或刷机了，它是唯一退路。

## 配置与数据

全部在本机 `~/.dsh/` 下，插件不联网、不上传任何东西：

| 文件 | 内容 |
|---|---|
| `boot-auth.json` | PIN 的 scrypt 哈希 + salt（不存明文） |
| `boot-totp.json` | TOTP 密钥 + 备用码的 scrypt 哈希 |
| `boot-recover.json` | 可选的邮件救援配置（收件地址 + SMTP 授权码） |

## 逃生口与回滚

| 场景 | 怎么做 |
|---|---|
| 忘了 PIN / 被锁 30 秒 | 点「用验证器 6 位码进入」，或填备用码 |
| 手机和电脑都不在手上 | 双击 `急救绕过.cmd`，创建一个标记文件，宿主看到就直接放行 |
| 想彻底撤掉 | 双击 `卸载.cmd`，或 `dsh plugin --profile desktop remove dsh-boot-handmade` |
| 想退回旧版本 | 双击 `回滚.cmd` 选择目标提交 |

> 急救标记是一个本地文件：`%USERPROFILE%\.dsh\boot-auth-bypass`。删掉它（或双击 `恢复锁定.cmd`）即恢复验证。
> **门不会因为"等久了"自己打开**——没有倒计时放行，也没有超时自动进入。

## 安全边界（请先读这段）

**它是仪式感 + 家用门闩，不是保险箱。**

- 这个锁保护的是**动画和验证这一层**，不是整个 Web 服务：懂技术的人可以打开开发者工具删掉遮罩节点，或者直接调宿主接口。
- 真正的强制门禁必须做在应用外壳前面（Electron 主进程 / 系统级），profile 插件够不着。
- PIN 是 scrypt 加盐哈希，会话令牌只在内存，错 5 次锁 30 秒；TOTP 密钥和备用码哈希都在本机。
- 但如果有人已经能读写你的用户目录，他可以直接删掉 `boot-auth.json` 绕过一切——这是本地锁的固有边界。

换句话说：别把唯一一份重要数据的访问权押在它身上。

## 常见问题

**Q：点「Windows Hello」后系统窗口没出现，或者出现在应用后面？**
A：插件会把 `Credential Dialog Xaml Host` 那个窗口强制置顶并抢前台。仍然没出现的话，先到锁屏试试指纹是否正常；不正常说明是本机指纹驱动在用户会话里起不来，需要修驱动，和插件无关。

**Q：验证器填了码一直说不对？**
A：确认填的是 6 位、且是**当前**显示的码（30 秒一换，插件容忍前后 60 秒）。手机和电脑时间差太多也会对不上。

**Q：动画太长 / 太闪？**
A：门在约 0.8 秒后就可操作，装饰文字在门后面并行播放，不阻塞输入。频闪和撕裂效果已移除。

**Q：能改成英文界面吗？**
A：目前界面文案是中文，代码里没有硬编码依赖，欢迎 PR。

## 技术细节

- 动画：纯 DOM + CSS + SVG，**没有图片、没有字体文件、没有构建步骤**
- 宿主半：一个 cordis 插件，注册 `/boot-auth/*` 路由
- PIN / 备用码：`crypto.scryptSync` + 随机盐
- TOTP：HMAC-SHA1，与 RFC 6238 官方向量对齐（仓库内 `tools/test_totp.mjs` 可复跑）
- 邮件救援：调用 Windows 自带 `curl.exe` 走 SMTPS，不引任何依赖
- 测试：`tools/test_boot_auth.mjs`（宿主 10 项）、`tools/test_totp.mjs`（24 项）、`tools/test_recovery.mjs`（14 项）

## 已知限制

- 应用内指纹依赖本机 Windows Hello 驱动；部分老驱动只能在锁屏用，应用内验证窗会拿不到采样。
- 启动画面从点击到出现仍受 Electron 本体启动时间影响，插件只负责"出现之后"的那段。
- 「直接进入（跳过验证）」是双入口模式的临时按钮，稳定几版后会移除。

## 桌面启动器（V4.1 起内置）

DSH 主进程要几秒才建出窗口，这段时间里连点图标只会拉起几个立刻退出的进程，
看起来像「点了没反应」。插件自带一个启动器脚本解决这个问题：

```
安装启动器.cmd     在桌面创建「DeepSeek Harness (Launcher)」快捷方式
卸载启动器.cmd     移除该快捷方式
launcher/          启动器本体（dsh-launcher.vbs + dsh-launcher.ps1）
```

点一下，约 100 ms 内弹出小窗显示「正在启动…」，主窗口出现后自动关闭；
如果 DSH 已经在运行，启动器直接把已有窗口切到前面，不会重复启动。

排错：`launcher/launcher.log` 会记录每次调用的每一步。

## 在应用内修改访问 PIN（V4.1 起）

门上有「修改访问 PIN」入口，不用退出应用、不用把 PIN 重置成未知状态：

- **刚验证过**（PIN / 指纹 / 动态码任意一种，5 分钟内）：直接填新 PIN 两遍即可
- **没验证过**：先填当前 PIN，再填新 PIN 两遍
- 改完**不会退出登录**，下次开门用新 PIN

为什么要有它：以前改 PIN 只能到门外重设，一旦中途失败，账号就进了死胡同。
现在改动是原子的——要么旧 PIN 还能用，要么新 PIN 已生效，没有中间态。

接口：`POST /boot-auth/pin/change`，参数 `{ next, confirm, current? }`。
宿主只在「5 分钟内刚验证过」或「当前 PIN 正确」时接受。

## DeepSeek 账号：由应用负责，门只负责带路（V4.1 起）

账号的登录与切换属于 DSH 应用本身，插件拿不到（核心的 `service-accounts`
没有对插件开放）。所以门上只做一件事：

```
门 →「DeepSeek 账号」→ 验证后进入 → 自动打开应用自带的账号菜单
```

**为什么值得做**：不是所有人都找得到那个入口。门在验证完成后会在 3 秒内查找
账号/头像元素并点开；找不到就什么都不做——此时人已经在应用里，界面和平时一样。

## 进门之后也能改 PIN（V4.1 起）

门的入口只在门出现时存在，进了应用就找不到了。所以进入后右下角会常驻一个
`⚿` 按钮，点开就是「修改访问 PIN」面板，参数与门内的那个完全一致。

- 需要当前 PIN（刚验证过 5 分钟内可留空）
- 改完不退出登录，下次开门用新 PIN
- 面板自带样式，不依赖门那套样式表（门关掉时会一起移除）

## 入口位置与撞车处理（V4.1 起）

入口挂在**左下角「已登录 DeepSeek」那一行**，而不是飘在角落——那里才是人会看的地方。

找不到时按顺序退：头像/账号元素 → 侧栏底部 → 标题栏 → 右下角浮标。

**防撞车**：插入后量一次矩形，和自己兄弟节点重叠就撤掉、退到下一个位置；
之后每 2 秒复查（最多 10 次），因为别的插件可能是稍后才注入的。
被挤掉时不会盖住别人的控件。

### 启动器卡在进度条怎么办

症状：小窗弹出来了，进度条跑满，但窗口一直不出现。

原因是**任务管理器里还留着一个没有窗口的 DSH 进程**，它占着单实例锁；
新进程启动后被它挡回来、立刻退出，所以什么都看不到。

启动器现在会识别这种情形：约 5 秒后把小窗文案改成「已有实例在后台，等待窗口」，
20 秒后提示「请在任务管理器结束 DSH 后重试」。真遇到了，按提示做一次即可。

## 桌面启动器（0.4.11 起恢复发布）

双击 `安装启动器.cmd` 会在桌面加一个 `DeepSeek Harness (Launcher)`，
点它会出现一个小窗：深色卡片、`DEEPSEEK HARNESS`、`正在启动…`、橙色进度条，
右侧是**百分比**。窗口一出现小窗就自己关掉。

进度条**最多只到 92%**，永远不会假装跑完——满格和"还在等"必须能一眼分清。

进度条上面还有一行字，说明**现在在做什么**，而不只是走了多少：

| 时间 | 步骤 |
|---|---|
| 0 – 1.2s | 正在启动进程 |
| 1.2 – 6s | 等待窗口出现 |
| 6s 以后 | 界面加载中 |

### 「进度条跑满但窗口不来」的根因（已修）

上一次异常退出会在后台留下**没有窗口的 DSH 进程**。它占着单实例锁，
新进程启动后立刻被挡回来并退出，于是屏幕上什么都不会出现。

现在启动器在拉起程序前先判断：

- 有窗口 → 聚焦已有窗口，不重复启动
- **没有窗口但有进程 → 认定为残留，全部结束，再干净启动**（日志写 `stale instances cleared`）

卸载：双击 `卸载启动器.cmd`。原有的 `DeepSeek Harness` 快捷方式从头到尾没被改过。

`安装启动器.cmd` 只是给本地用；装了插件的人不需要跑任何脚本：

```
右下角 / 左下角的入口 → 「启动方式（可选）」→ 启用桌面启动器
```

- **默认不装**，旧的快捷方式一直可用
- 启用后桌面多一个 `DeepSeek Harness (Launcher)`，点下去立刻有反馈
- 不满意点同一处「卸载启动器」，旧入口从未被动过

之所以做成选装：新入口解决的是「连点好几次」的体感问题，但它依赖 DOM 与窗口行为，
不是所有机器都需要，也不该在没验证过的情况下替用户做主。

## 入口改叫「更改登录细节」（V4.1 起）

这块面板现在管两件事，所以入口名不能只写改 PIN：

```
鼠标移到「更改登录细节」上
 ├─ 更改登录        → PIN 表单
 └─ 更改启动方式    → 桌面启动器开关
```

名字取“细节”是因为找的人不一定是在找密码——也可能是想换启动方式。
单独写「更改登录密码」会让另一半功能显得不存在。

## 指纹采样失败后的自愈（V4.1 起）

Windows 把 Hello 提示框放在 **CredentialUIBroker.exe** 里，而且会**复用**这个进程。
如果在采样中途把窗口关掉（点取消、按 Esc、直接关），broker 会保留一次失效的采样会话：
下一次窗口照样弹出来、也显示「请扫描指纹」，但**采不到任何东西**，只有重启才行。

现在两种处理：

- **自动**：这次 Hello 返回 Canceled / RetriesExhausted / no-result 时，宿主先
  `taskkill /F /IM CredentialUIBroker.exe` 再自动重试一次
- **手动**：`POST /boot-auth/hello/reset` 随时清掉卡住的 broker

代价是重试会多弹一次窗；但比“指纹彻底用不了、只能重启”好。

## 进门后的入口

右下角常驻 `⚿` 浮标，点开是「更改登录 PIN」。它完全在我们自己的 DOM 里，
不碰应用界面的框架节点（之前挂进标题栏把界面卡死过，那条路废了）。

进应用后的那个 `⚿` 浮标曾经有两种实现：挂进应用标题栏（后来确认会把界面卡死，
因为那部分 DOM 归 React 管），以及右下角浮标。两者在当前版本上都不稳定，故整段移除。

现在能改 PIN 的唯一位置是**门本身**（「更改登录密码」）。它不碰应用界面，是安全的。
桌面启动器改用 `安装启动器.cmd` 安装，不再依赖应用内入口。

## 层级与点得到（V4.1 起）

别的插件也在往右下角放东西，层级低于它们就会变成"看得见、点不到"。三层保障：

1. **门**：`z-index: 2147483640` + `isolation: isolate`——锁不该被任何插件盖住
2. **常驻入口**：`2147483645`，面板 `2147483646`
3. **运行时自检**：挂上 400ms 后用 `elementFromPoint` 量一次自己是不是最上层；
   被挡就重新 append 到 `documentElement` 末尾（同层级里后者赢），还被挡就上移一格

第 3 条会往控制台写一行 `entry was covered by <对方>`，方便以后定位是谁在抢位置。

## 面板关不掉（V4.1 起）

现象：点叉号没反应，反而听到余额挂件「叮」一声——因为那块角落同时被别的挂件占着，
它的点击层压在我们的叉号上。

修法不是抢赢了事，而是让关闭有三条独立的路：

1. **叉号**（34×34 热区、面板内 `z-index: 5`）
2. **Esc**（键盘，完全不经过那块区域）
3. **点面板外面任何地方**

面板整体也从 `right:20px` 让到 `right:84px`，不再和挂件重叠。

## 开机耗时记录

每次启动，门会把几个关键节点上报给宿主，追加到：

```
~/.dsh/boot-timing.log
```

格式是 `时间戳  相对毫秒  阶段`，阶段包括 `run-start`、`gate-ready`、`unlocked`、`finish`。
启动器自己的时间线在 `launcher/launcher.log`。

两处加起来就能回答「哪一段慢」，不需要开控制台。

## 新用户怎么知道有启动器（0.4.11 起）

装了插件的人不会自己找得到新入口，所以补了四件事：

1. **入口自愈**：`ensure` 会检查桌面快捷方式。说好装了却不见了（误删、清理工具），
   就静默补一个回来。
2. **一次性公告**：进入应用后弹一次「现在有了新的启动方式」，里面有一段和启动器
   一致的**步骤 + 百分比**示意，让人知道等待时长什么样。
3. **避让其他弹窗**：弹之前扫一遍其他插件的 modal / 更新日志 / toast。有就每 1.5 秒
   再看一次，最多等 60 秒；它们说完了才轮到自己。这条通知不急，不该插队。
4. **按版本记忆**：勾选「下一次更新前不再展示」会写进 `~/.dsh/boot-announce.json`，
   记录的是**版本号**而不是布尔值——发新版本会自动重新提示一次。

接口：`POST /boot-auth/announce`，`action` 为 `status` / `dismiss` / `ensure`。

## 没设过 PIN 的人怎么办（0.4.11 起）

插件第一次跑的时候 `boot-auth.json` 还不存在，门会进入**设置模式**：

```
为了让这把锁生效，请先为它设置一个 PIN（4-32 位数字）

  ○ ○ ○ ○          ← 先给 4 格，够 4 位就是一个完整 PIN
  [1][2][3] …      ← 可视化键盘

输完第一遍 → 提示「请再输一次这个 PIN，确认没有按错」
两遍一致   → 写入并放行
两遍不一致 → 清空重来，不会把错误的那一次写进去
```

**为什么必须输两遍**：以前只输一次就生效，一个手滑就把自己永久锁在外面——
而那时唯一的出路是 `急救绕过.cmd`，等于锁白做了。

另外，点是**自适应**的：4 位时显示 4 格，第 5 位开始才多一格，到 8 位封顶。
不会让人觉得"还有 4 格没输完"。

## 所有密码输入都能看明文（0.4.11 起）

门上的点旁边多了个「显示」按钮；设置里改 PIN 的三个框上方有「显示输入内容」勾选。

- 打开后点变成**真正的数字**，`1 2 3 4` 一目了然（数字槽 22px 宽，不会溢出压到按钮）
- 能核对「我输入的是不是我想的那个」
- 记不住的人可以**拍照留存**——全是一样的点，拍照没有任何意义

默认关闭。这是本地 UI，不上传、不记录，除了你自己没人看得到。

## 「直接进入」保留到 0.5.0（决定，不是遗漏）

门上有一个 `直接进入（跳过验证）`。它不是忘了删，是**故意留的退路**：

> 现在还不知道会不会出现结构性的 bug 让人根本进不来。真有那一天，
> 「看起来像锁」没有意义，「进得去」才重要。

计划在 **0.5.0** 移除，前提是这之前没有出现过"门本身进不去"的问题。

在那之前，能救急的三条路，按代价从低到高：

| 办法 | 做什么 | 恢复 |
|---|---|---|
| 直接进入 | 门上点一下，跳过验证 | 无副作用，随时可用 |
| `急救绕过.cmd` | 在 `~/.dsh/` 放一个 `boot-auth-bypass` 标记文件 | 删掉标记即恢复 |
| `回滚.cmd` | 停用插件本体 | 重新启用即可 |

前两条都**不碰你已经设置的 PIN**，只是临时放行；第三条是把插件关掉。

## PIN 长度：4–32 位（0.4.11 起）

最早限定 4–8 位，那是我拍的数字，不是任何标准。现在放宽到 **4–32 位纯数字**：

- 键盘只有 0–9，所以不会出现"按不出来的字符"
- 超过 8 位时点会**自动换行**，不会挤出屏幕
- 门的输入框、设置里的改 PIN、宿主校验三处一致

同时删掉了门下方那行内部备注「双入口模式 · 稳定后会把「直接进入」移除」——
那是给开发者看的，不该出现在用户的界面上。

## 门只管进门（0.4.11 起）

门上原本还塞了一个「更改登录密码」表单，和设置里的那份重复。现在门上只剩通过验证需要的：

```
数字键盘 + 显示
WINDOWS HELLO · 指纹 / 人脸 / PIN
用验证器 6 位码进入（配好了才显示）
DeepSeek 账号
直接进入（跳过验证）
```

改 PIN、改外观、开关启动器小窗，全在左侧栏的「⚙ 设置」里。

## 门的输入：一个普通密码框 + 眼睛按钮（0.4.11 起）

自绘的点、屏幕键盘、可变槽位——全部撤掉。回到最稳的形态：

```
输入登录密码 · 已输入 9 位
[ ● ● ● ● ● ● ● ● ● ]  [👁]  [解锁]
```

- 输入框就是浏览器的密码框，输入、退格、粘贴、回车全部原生行为
- 右边一个眼睛按钮：**闭眼**时是点，点一下变**睁眼**，点立刻变成数字；
  再点一下回到闭眼，数字变回点
- 图标和颜色跟随深浅主题（深色下是浅灰/米白）
- 位数写在提示行（`已输入 9 位`），因为 9 位以上靠肉眼数点容易数错

切换只改 `input.type`，**不碰输入值**，所以不存在"点一下就清空"。
